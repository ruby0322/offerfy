六條讓它夠泛用的規則

    
    
      
  • R1 只認形狀，不認名字。不是 allowlist #work / #edu，而是認「#某個名字(...) 裡的 key: "字串字面值"」。所以 #project、#cvitem、任何套件自己的元件都自動認得，欄位標籤直接用那個 key。
    • 
      
  • R2 絕不 fallback。認不出來的行永遠不會變成輸入框。舊版把 #project(、name: "..."、) 各自變成一個可編的「內文」欄位——那是最糟的失敗，因為使用者改了它就會把語法寫進文件。
    • 
      
  • R3 #let 一跳間接。author: name 的值不是字面值，所以往上找 #let name = "..."，欄位指到那個字串。沒有人引用的 #let 會被標成死綁定。
    • 
      
  • R4 一個文字範圍就是一個編輯單位。一條要點是一個可編輯面，*粗體* 和 #link("url")[文字] 是裡面的格式、不是另一個欄位——一句話在人眼裡是一件事，在這裡也是。行內的 run 只用來渲染和序列化。
    • 
      
  • R5 逃脫策略以原文為準。canonical set 之外，這一段原本就逃脫過的字元繼續逃脫。所以 Projects & Achievements 的裸 & 和 Systems Analysis \& Design 的 \& 都能原封不動回去——這是「每個模板寫法不一樣」的直接解法。
    • 
      
  • R6 單位要通過 serialize(parse(slice)) === slice 才可編。過不了就唯讀，不會悄悄改寫。解析器產生的序列化和 DOM 產生的序列化必須在未改動的單位上逐 byte 相同——那個等式就是這個編輯面安全的依據。
    • 
    

    
粗體和連結就是選字套格式

    
    
      
  • 選一段字，旁邊就會浮出一條小工具列：B、I、連結。鍵盤是 ⌘B／⌘I／⌘K——⌘K 直接把網址欄打開、游標已經在裡面，打完按 Enter 就套上去，整個手勢不用離開那句話。點已經存在的連結也會浮出同一條工具列，網址填好的，可以改或移除。
    • 
      
  • 要讓它成立只有一個細節要小心：游標移到網址欄的那一刻，瀏覽器會把你在文字上的選取丟掉。所以工具列打開時就把 Range 複製一份，套用前再還原回去——這是「打網址不會丟失選取」的全部原因。
    • 
      
  • 原理：套完格式之後把整個編輯面序列化回 Typst，換掉這一行自己那一段 span，其餘位移。所以它是改值，不是結構操作——不重新解析、不重新渲染表單，和打字走同一條路。
    • 
      
  • 巢狀現在可以。解析器會遞迴進 *…* 和 #link(…)[…]，所以粗體裡放連結、連結文字裡放粗體都能原樣回去。
    • 
      
  • 字串參數還是放不了格式。title: "*x*" 在 Typst 裡會把星號原樣印出來。點到那種格子工具列會整排變灰，並說明原因——要讓職稱能有粗體，得版型那邊把參數改成收內容區塊 […]，那是版型 API 的事。
    • 
    

    
新增用抄的，不用寫死的範本

    
    
      
  • 「照這個段落的寫法加一筆」會把那個段落最後一個區塊的原始碼複製一份、把每個字串值換成「（待填）」。所以在 #project 段落它生 #project，在 #work 段落它生 #work，連 dates-helper(...) 的寫法都跟著。真機該改用 emitter 自己的 heading_block / bullet_lines，理由一樣：產生和解析要共用同一份文法。
    • 
    

    
哪些是真的、哪些是假的

    
    
      
  • 真的：解析器、行內標記的 run 切分、span 位移、逃脫策略、Tier 判定、解析報告、復原堆疊、新增用的形狀複製。
    • 
      
  • 假的：編譯閘門在這裡是括號與引號的平衡掃描，真機跑 typst compile；hash 是 FNV-1a，真機是 sha256。
    • 
      
  • 表單不顯示文件設定（#import、#set、#pagebreak）和註解——它們不能編也不是內容，但解析報告會逐項列出來，所以沒有被偷偷忽略。沒人引用的 #let 留著，因為它可以刪。
    • 
      
  • 還沒做：多行段落合併成一段（現在一行是一個單位）、#grid / #table 這類有自己內部結構的容器、以及 layout.py 的頁數與行數回饋。
